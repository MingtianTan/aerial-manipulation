Develop mode: pipeline and reading list

The planned pipeline for the next phase, where each part comes from, the papers to read for it, and the references the main page already cites. Each entry says what the paper does and what it means for the Flight DiT and π0.5. Entries marked closest to us are the nearest to our design.

Pipeline, November 2026

Plan for the next phase as of 8 Nov 2026, built from the reading list below and a check of the AM-Bench and OpenPI code. It replaces the plan of 2 Nov; Part 1 of the main page shows the same pipeline.

  • Two learned modules, one IK. The Flight DiT and π0.5 are trained separately and exchange messages in both directions; base and arm are still solved together by the Pyroki floating-base IK that recorded every demonstration. A hard split into a flight controller and joint servos is an ablation, not the plan.
  • π0.5 keeps its action space and its checkpoint. It starts from the 30k checkpoint (81.1 %) and still outputs 50-step chunks of 8-D end-effector targets at 20 Hz. No arm-joint or base target is recorded in the 4,800 demonstrations, so the earlier aarm = [q1, …, q4, gripper] has no labels.
  • Down: a forecast of the base, packed as 11 tokens. The Flight DiT predicts where the base will be over the next 2.5 s. Ten waypoints of that path, in the end-effector frame of the chunk start, plus one token with a latent, the message's age, a contact gate and the body velocity enter π0.5's action expert ahead of the 50 action tokens. π0.5's state input carries only the gripper width, so this is the only body information it gets.
  • Up: π0.5's chunk with its age. At every tick the Flight DiT reads the chunk π0.5 is executing and how old it is, so the base plans around what the arm is about to do.
  • Three clocks. IK and PID at 120 Hz, the Flight DiT at 20 Hz (one tick per camera frame), π0.5 re-planning every 8 executed actions (2.5 Hz). In M1 the Flight DiT only informs π0.5; in M2 every tick also moves the IK's base reference, which is where the faster loop acts on the vehicle.
  • π0.5's backbone stays as it is. The VLM and SigLIP are frozen; only the action expert, its input and output projections, the time MLPs and the two message projections train. The full fine-tune is a comparison arm.
  • Open gaps, rechecked on 7 Nov. No learned aerial manipulation policy with an arm takes the wrench as an input, and no work keeps a pretrained arm VLA while a separately learned body module sends it a message. DUET keeps the arm VLA swappable but sends nothing back; HAF freezes the VLA but generates locomotion inside it.
  • Changed since 2 Nov. π0.5 keeps the 8-D end-effector chunk instead of arm joints, and the low level stays one IK instead of a flight controller plus joint servos.
  • Fflight is 11 tokens (a forecast plus one latent token) at the input of the action expert, instead of one token at "an intermediate layer or the action expert".
  • Flight labels come from the measured 120 Hz base path, and Δψ is dropped, because the IK holds base yaw fixed in every demonstration.
  • Stage B freezes π0.5's VLM instead of training all parameters; the full fine-tune becomes a comparison.
  • New: the return channel from π0.5 to the Flight DiT, and the Flight DiT's path as an optional IK reference (M2). Contact goes into the Flight DiT in Phase 2; drawing it into π0.5's images is the comparison arm.

How it runs

  • Order within one physics step. Flight DiT tick → message → π0.5 re-plan → IK. In simulation both models are awaited, so ages are set by the schedule alone: 0 for the message π0.5 reads, 6 to 48 physics steps for the chunk the Flight DiT reads.
  • Old or missing messages. The age is part of the message (RAVEL, TIC-VLA); the Flight DiT holds the last chunk (DuoCore-FS); a missing chunk or message is masked with a valid flag of 0 (FWBC-VLA). Stage B draws each message from 0–6 physics steps earlier and drops it with probability 0.1, so late and absent messages are in the training distribution.
  • Base reference at tick boundaries (M2). The PID differentiates the IK's base target for its feed-forward (clamped to ±1), so a jump in the base path would make a thrust spike. Each new path is first clipped to the IK's base limits (walls, doors, windows), then blended in over 6 physics steps and rate-limited.
  • On hardware. π0.5's first action takes 272.86 ms with full denoising and 93.45 ms with RAVEL's rolling inference (median, PyTorch, one RTX 4090), so chunk boundaries would use real-time chunking: freeze the actions that will execute and inpaint the rest, without retraining. The 40 M Flight DiT variant exists for the onboard compute budget.

Separate or joint control

  • Decision: separate policies, one IK. Two generators with no gradient between them and messages in both directions; base and arm still solved by one floating-base IK whose base reference can follow the Flight DiT. A hard split is only an ablation.
  • The data decide the arm side. π0.5's 81.1 % recipe outputs 8-D end-effector chunks; no arm-joint or base label is recorded. The only other representation OpenPI accepts, 12-D base plus joints, has no recorded data, and AM-Bench registers that interface for 3 of the 12 tasks.
  • Evidence for a separate body module and a dedicated channel. AIR-VLA+: separate flight and arm decoders score 48.0 against 42.0 for single-head π0.5. Opt2VLA: a body signal as a dedicated token, 74.4 % against 27.8 % when concatenated into the state. Cracking Mobile Manipulation: arm skills at 80 % fall to 19 % when composed on a moving base.
  • A hard split is risky here. Interfaces that expose only part of the body make some tasks unreachable by construction (OpenHLM); every demonstration comes from one IK that couples base and arm at each step; FA-Hexa's arm (three pitch joints and a wrist roll) cannot absorb a sideways base error; the 12-D direct interface exists for 3 tasks.
  • One whole-body π0.5 is a baseline, not the plan. No base-joint dataset exists. The scene-scale aerial VLA (π0.5 with LoRA, one 8-D whole-body chunk; 65.0 % on local skills) is cited, and the whole-body route is run only on the three tasks with a base-joint interface.

Keeping π0.5 intact

  • Frozen VLM and SigLIP. After the bf16 cast they are bit-identical to the 30k checkpoint; behaviour can change only through the action expert and the new projections (RAVEL; Knowledge Insulation).
  • No gradient path between the models. Messages are computed offline and the Flight DiT is frozen in Stage B (AIR-VLA+: 40.4 → 45.1 with the detach; InCoM: 37.2 % without the stop-gradient against 40.5 %).
  • The backbone never looks at the message. The flight tokens sit in the suffix, which the prefix cannot attend to, so the prefix and its KV cache are unchanged: the same one-way flow Knowledge Insulation uses.
  • A bridge that has to carry information. A small random initialisation (Wiring Matters) plus message dropout, so "no message" stays a defined input and the zero probe is in distribution.
  • Short, low and fixed in advance. Low learning rate, short schedule, EMA, one checkpoint chosen beforehand. The Flight DiT trains on all five conditions; every π0.5 arm sees the same 1,728 demonstrations, half default and half 10 % wind.
  • Why freeze. For attribution and protection, not because freezing is known to be better: Opt2VLA's frozen VLM beat full fine-tuning (82.2 % against 75.6 %, with one task making the difference), while Per-Group Error's frozen-backbone π0.5 lost on hardware (3.75 against 4.0 of 4).

Open decisions

  • Phase 1 as a separate pilot, or folded into Phase 2. Folding it in makes the TAP-drawing arms Phase 2's comparison and moves the sort-by-weight task past the deadline. To confirm.
  • Image features for the Flight DiT. DINOv2-S (≈ 2 GB cache) or pooled SigLIP features from the π0.5 checkpoint (≈ 24 GB).
  • The M2 weight. w of 0.5, 1 or 2 against the IK's smoothness weight of 1, and whether overlapping base paths are averaged before the IK.
  • Data arms. The default demonstrations only, or also a 4,800-demonstration pair with its own control (≈ $120–150).
  • Flight DiT size and start. RDT-170M weights or from scratch; 170 M or 40 M as the headline model.
  • Contact signal for Phase 2. ContactSensors on the fingers plus a telemetry re-record (2 tasks × 2 conditions × 80, about a GPU-day per condition), or the commanded wrench rebuilt offline.
  • Serving. The Flight DiT inside the evaluator or as a second server; π0.5 on a remote server if one 16 GB card cannot hold Isaac, π0.5 and the Flight DiT together.
  • Task input. A 12-way one-hot, or a frozen text embedding of the instruction.
  • Yaw. Whether a re-recording with free base yaw is worth it to give Δψ a label.

Arm VLA and body module: how they communicate 17 items · 31 systems in the table

The coupling between the arm model and the body model, read as a communication channel: what is sent, in which direction, where it enters, how often, and what the receiver does with an old message. The table compares 31 systems; entries below cover the ones not described elsewhere on this page.

  • Most channels point down. The VLA sends a command to a controller: an end-effector pose or trajectory (UMI on Legs, Aerial Manipulation in the Wild, the scene-scale aerial VLA), a base twist (Tabletop to Walking Bot, WholeBodyVLA, Ψ0), a full joint reference (OpenHLM), or a learned latent (LeVERB 256-d, SONIC 64-d). OpenHLM found that interfaces exposing only part of the body make some tasks unreachable by construction, though its decoupled arm-joints-plus-navigation interface still won one of three tasks.
  • Body-to-arm channels are rare, and they enter the action expert, not the VLM prefix. FWBC-VLA (force tokens, gated cross-attention), HEX (50-step body-state forecast, sigmoid-gated residual) and Opt2VLA (torque history as one dedicated token: 74.4% against 27.8% when concatenated into the state). None of them sends a learned motion intent from a separately trained body generator, which is what Fflight is.
  • Inside one model, the body conditions the arm by cascade or exchange. BEHAVIOR Robot Suite runs base → torso → arms, AC-DiT and HiRe-MoMa pass base features to the arm, InCoM and MoPA exchange both ways in every block, and AIR-VLA+ runs arm → UAV. With separate modules, DUET and ALMA pass the arm's joint positions to the body only as observations; neither sends the arm's commands or plan.
  • Old messages are handled three ways. Hold the last one and train with the same delay (Helix, DuoCore-FS, LeVERB, Ψ0), give the message's age as an input (RAVEL, TIC-VLA), or timestamp a trajectory and blend (UMI on Legs, the scene-scale aerial VLA).
  • The channel we use. One-way suffix tokens in π0.5's action expert (Opt2VLA, DreamTrajectory) carrying a forecast of the base (HEX) and its age (RAVEL, TIC-VLA), trained under random delay (DuoCore-FS, T-Rex), with no gradient between the two models (InCoM, AIR-VLA+), and π0.5's chunk sent back up. Shifted token positions, a zero-gated AdaLN entry (RoboMME's modulator family) and prefix tokens are the comparisons, and joining the KV cache (PanoVLA) is further reading; see the pipeline.

Where a signal enters the action model

  • Wiring Matters: Injection Topology and Initialization of Affordance Heads in Vision-Language-Action Policies (An et al., arXiv 2026) injection: on StarVLA's QwenPI, a π0-style VLA on Qwen3-VL-2B, a dense affordance head reads the model through a stop-gradient and writes its features into every conditioning layer of the action expert. Residual wiring with random (active) initialisation reaches 96.2% on LIBERO against 93.1% without the head; without the stop-gradient 85.5% (a preliminary configuration). Zeroing an active bridge at test time cost 28 points on LIBERO-Goal in preliminary experiments, while zeroing a zero-initialised one costs nothing (94.8% → 95.6%): such a bridge only regularises training. For us: why the message projections start from a small random initialisation rather than zero, why nothing flows back from π0.5's loss into the Flight DiT, and why zero, shuffled and oracle messages are the probes.
  • RoboMME: Benchmarking and Understanding Memory for Robotic Generalist Policies (Dai et al., ICML 2026) Project page see Figure 2: Figure 2 lays out three ways to add a signal to π0.5: as context (tokens joined to the VLM input), as a modulator (action features cross-attend to the signal and produce AdaLN scale and shift in the action expert), or as a separate expert with block-wise causal attention. Across 14 variants and 16 tasks, frame sampling with the modulator scored highest among the non-oracle variants (44.51%) and won 25 of 40 real trials against 4 for π0.5; the modulator is the most effective entry for perceptual memory, but no single design wins every task. For us: the three families an input to π0.5 can take. Our message is a dedicated token stream in the action expert; the zero-gated AdaLN entry is the modulator ablation.

VLA + DiT on mobile and legged platforms

  • HEX: Humanoid-Aligned Experts for Cross-Embodiment Whole-Body Manipulation (Bai et al., arXiv 2026) Project page closest to us: a Qwen3-VL-2B VLA with a flow-matching action expert drives arms and hands, RL controllers drive the legs from a mode-and-motion command, and a mixture-of-experts proprioceptive predictor (a 4-layer transformer, hidden 768) forecasts 50 future body states that are fused into the action head through a sigmoid-gated residual. Trained jointly with an auxiliary future-state loss; 73.34 ms per inference on an RTX 4090. For us: the nearest structure to Fflight: a body-dynamics forecast feeding the action model. We copy the payload, a forecast of the body, but train the forecaster separately and send its output as tokens.
  • Opt2VLA: Force-Aware Vision-Language-Action for Contact-Rich Humanoid Whole-Body Manipulation (Liu et al., arXiv 2026) Project page closest to us: a GR00T VLA with a frozen VLM sends hand and foot waypoints plus a contact-force reference down to RL whole-body controllers, and gets the sensed torque history back as one dedicated token in its action decoder. VLA 5 Hz, commands 50 Hz, controllers 200 Hz. For us: the most direct evidence for our choice: a body-side signal as one dedicated action-decoder token reached 74.4% joint success against 27.8% when concatenated into the state (Table III, 30 trials per task), and the frozen-VLM setting beat full fine-tuning, 82.2% against 75.6%. That setting still trains the VLM's normalisation layers and connectors, and one task (shelf pushing, 70.0% against 50.0%) makes the difference.
  • InCoM: Intent-Driven Perception and Structured Coordination for Mobile Manipulation (Liu et al., arXiv 2026) Project page closest to us: separate flow-matching decoders for base and arm exchange one learnable Trend Token per branch by cross-attention in every block, with a stop-gradient on the other branch's features; it argues that one-way conditioning, as in AC-DiT, misses the arm's effect on the base. On PrepareGroceries: 40.5% for the full model, 36.1% with one-way interaction, 37.2% without the stop-gradient, 34.7% without the Trend Token. For us: the reason for the return channel from π0.5 to the Flight DiT and for keeping gradients apart. Their branches run in lockstep inside one model; ours are trained separately and run at different rates.
  • DreamTrajectory: Trajectory-Guided Action Generation with World Model Alignment for Mobile Manipulation (Yang et al., arXiv 2026): inside π0.5's action expert, a stream of 16 planned end-effector waypoints is denoised alongside the whole-body chunk under a group-causal attention mask (actions see the waypoints, not the reverse); the trajectory head adds 0.017 M parameters, and a GRU world model ranks perturbed candidate chunks at test time. Trajectory guidance raises MS-HAB success from 32.3% to 47.5%, test-time refinement to 54.8%. For us: the template for the message's one-way token stream inside π0.5's action expert. Ours comes from outside π0.5 instead of being denoised with the actions.
  • Ψ0: An Open Foundation Model Towards Universal Humanoid Loco-Manipulation (Wei et al., RSS 2026) Project page: a frozen Qwen3-VL-2B conditions a 500 M MM-DiT action expert through joint attention; the expert outputs arm and hand joints plus an 8-DoF lower-body command to an RL policy, with asynchronous inference and training-time real-time chunking. For us: the same frozen-VLM plus separately trained DiT split, with random delay masking in training to bridge the slow VLM and the fast controller.
  • OpenHLM: An Empirical Recipe for Whole-Body Humanoid Loco-Manipulation (Hu et al., arXiv 2026) Project page: π0.5 outputs a 34-D whole-body joint reference to a motion tracker. In mean task progress on three tasks the joint interface scores 86.7, 80.0 and 85.0, against 66.7, 93.3 and unreachable for a decoupled arm-joints-plus-navigation interface; a VR 3-point and an SMPL interface do worse, and a 0.2 s reference preview gives 67% progress where 0.6 s gives 13% and 0 s stutters. For us: interfaces that expose only part of the body make some tasks unreachable by construction, which is why our split stays inside one IK; the preview result suggests how far ahead Fflight should look.
  • SONIC: Supersizing Motion Tracking for Natural Humanoid Whole-Body Control (Luo et al., Science Robotics 2026) Project page: a large motion-tracking RL controller exposes a quantized 64-d universal motion token; a fine-tuned GR00T N1.5 predicts that token plus hand joints, and the token goes straight into the controller's decoder. For us: the opposite direction, VLA to body, but the same idea of a compact learned latent as the channel; the authors credit the quantized token space for an easier action space.
  • PhysiFlow: Physics-Aware Humanoid Whole-Body VLA via Multi-Brain Latent Flow Matching and Robust Tracking (Qin et al., arXiv 2026): a 256-d vision-language latent enters a flow-matching motion generator as a prefix token at 10 Hz; its 50 Hz references go to an RL tracker, and the tracker's error is backpropagated through the frozen tracker to fine-tune the generator. For us: training one module against a frozen downstream one is a workable way to make the channel physics-aware, like training the Flight DiT against a frozen π0.5.

Slow-fast channels worth keeping

  • Helix: A Vision-Language-Action Model for Generalist Humanoid Control (Figure AI, technical report 2025): a 7–9 Hz VLM sends one continuous latent to a 200 Hz policy as a prefix token; the two are trained end to end with the deployed latency offset. For us: the canonical single-latent channel across rates, the same shape as Fflight with the roles reversed.
  • GR00T N1: An Open Foundation Model for Generalist Humanoid Robots (NVIDIA, arXiv 2025): a 10 Hz VLM and a 120 Hz DiT action module; the DiT cross-attends to the VLM's layer-12 tokens in alternating blocks, and both are trained jointly. For us: the standard VLM-plus-DiT layout, and a reference for which π0.5 layer the Flight DiT could read.
  • Asynchronous Fast-Slow Vision-Language-Action Policies for Whole-Body Robotic Manipulation (Zou et al., arXiv 2025): DuoCore-FS: a 1–3 Hz VLM writes embeddings to a buffer that a 25–30 Hz diffusion decoder reads every step, reusing the last entry until a new one arrives; trained end to end with a random delay between the two (Δ ∼ U[0, 25] frames). For us: the template for holding the last message and for training under delay.
  • RAVEL: Asynchronous Rolling Inference for Flow-Based Vision-Language-Action Models (Chen et al., arXiv 2026) closest to us: π0.5's action expert reuses the latest VLM context with its age added to the timestep embedding, and a fast observation path enters selected expert layers through gated cross-attention adapters. With the age given (temporal-offset conditioning) success rises from 78.00% to 97.85% on LIBERO and from 31.54% to 46.82% on RoboTwin; π0.5's first-action latency falls from 272.86 ms to 93.45 ms (PyTorch, one RTX 4090); the real-robot runs use 30 Hz control. For π0.5 the vision-language backbone is frozen and only the expert, the action projections and the timestep and offset MLPs train; the fast observation path was tested on a DynamicVLA checkpoint, not on π0.5. For us: π0.5 with a frozen VLM and the context's age as an input to the action expert: the closest ready design for our Stage B freeze set and for the message's age.
  • TIC-VLA: A Think-in-Control Vision-Language-Action Model for Robot Navigation in Dynamic Environments (Huang et al., ICML 2026): the action policy cross-attends to the cached VLM KV together with the explicit delay and the ego-motion since reasoning began, and is trained with injected delays. For us: Fflight could carry its own age and the vehicle motion since it was computed.
  • Real-Time Execution of Action Chunking Flow Policies (Black et al., NeurIPS 2025) Project page chunk boundary: real-time chunking (RTC) generates the next chunk while the current one executes, freezing the actions that will execute and inpainting the rest, with no retraining. Tested on 12 dynamic Kinetix tasks and 6 real bimanual tasks with π0.5, including runs with 100 and 200 ms of added latency. For us: how π0.5 would take a new message mid-chunk on hardware; in simulation both models are awaited, so the simulation study does not need it.
  • Training-Time Action Conditioning for Efficient Real-Time Chunking (Black et al., arXiv 2025): simulates the inference delay during training and conditions on the committed action prefix, so real-time chunking costs nothing at inference; better than inference-time RTC at larger delays in simulation, on par with it on π0.6 in the real world. For us: the training-time version of our delay augmentation.

Also checked: humanoid loco-manipulation systems found in the same search and not read in detail: HALOMI, TrajBooster, HANDOFF, KINO.

Adding an input without damaging the VLA 7 items

Background for Stage B: how to add the message to π0.5 and keep what the pretrained model knows.

Two findings shape Stage B. A freshly initialised action-side module damages the backbone unless its gradients are kept out (Knowledge Insulation), and π0.5's VLM can stay frozen while only the action expert learns to use a new input (RAVEL, in the communication section). The 2026 alternatives are a frozen copy of the pretrained expert with a trainable one beside it (PriorVLA), separation without freezing (UAM), parameter-efficient experts (VLA-GSE) and weight interpolation after the fact (RETAIN). Freezing is not free: one frozen-backbone π0.5 lost to the full fine-tune on hardware (Per-Group Error, in the wheeled section).

  • Knowledge Insulating Vision-Language-Action Models: Train Fast, Run Fast, Generalize Better (Driess et al., arXiv 2025) Project page insulation: adding a flow-matching action expert naively harms both training speed and the VLM's knowledge. The fix: the expert reads the backbone's keys and values through a stop-gradient, no backbone token attends to the expert, and the backbone learns from discrete FAST action tokens and vision-language data instead. On DROID 0.55 ± 0.09 against 0.49 ± 0.09 for π0 (the error bars overlap); training is as fast as π0-FAST, where π0 needs 7.5 times the steps. For us: the reason π0.5's VLM is frozen in Stage B and the message sits where the backbone cannot attend to it. We freeze rather than co-train because the project has no vision-language data to mix in.
  • ControlVLA: Few-shot Object-centric Adaptation for Pre-trained Vision-Language-Action Models (Li et al., arXiv 2025) Project page: a ControlNet-style branch adds object-centric conditions to a pretrained policy through zero-initialised KV-projection layers, so the first fine-tuning step leaves the policy unchanged; 76.7% over six short-horizon real tasks with 10–20 demonstrations each. The base is a 29 M DiT pretrained on DROID, not π0. For us: the zero-initialised route, our adaRMS ablation; read it with Wiring Matters, which finds such bridges can stay unused.
  • PriorVLA: Prior-Preserving Adaptation for Vision-Language-Action Models (Guo et al., arXiv 2026) Project page: keeps a frozen Prior Expert as a read-only source and trains a parallel Adaptation Expert, fed through Expert Queries with scene priors from the VLM and motor priors from the Prior Expert; it updates 25% of the parameters full fine-tuning would. 11 points above π0.5 on RoboTwin 2.0-Hard and 99.1% on LIBERO; with 10 demonstrations per task, 48% in distribution and 32% out of distribution, 24 and 22 points above π0.5. For us: a fallback for Stage B if training our action expert drifts on default: keep the 30k expert frozen and train a copy beside it that reads the flight tokens.
  • UAM: A Dual-Stream Perspective on Forgetting in VLA Training (Zhang et al., arXiv 2026): names the "embodiment tax": fine-tuning a VLM on action data erodes its multimodal skills. A parallel Dorsal Expert, initialised from a pretrained generative model and trained to predict visual dynamics, takes over the control-relevant features; trained end to end with no freezing, no stop-gradient and no vision-language co-training, the model keeps over 95% of the VLM's multimodal capability. For us: evidence that separation alone can protect the backbone; relevant if the full fine-tune (B-full) turns out better than the frozen one.
  • VLA-GSE: Boosting Parameter-Efficient Fine-Tuning in VLA with Generalized and Specialized Experts (Jiang et al., arXiv 2026) Code: full fine-tuning overfits and forgets the vision-language skills; VLA-GSE splits the frozen backbone spectrally into shared and routed experts and trains 2.51% of the parameters: 81.2% zero-shot on LIBERO-Plus, with vision-language skills kept about as well as with LoRA. For us: a middle ground between our frozen VLM and B-full.
  • Actions as Language: Fine-Tuning VLMs into VLAs Without Catastrophic Forgetting (Hancock et al., arXiv 2025): VLM2VLA writes low-level actions as natural language so that LoRA alone turns a VLM into a VLA without catastrophic forgetting; checked with VQA studies and over 800 real-robot experiments. For us: a reminder that the forgetting comes from the action data's distribution shift; our frozen VLM never trains on it.
  • Robust Finetuning of Vision-Language-Action Robot Policies via Parameter Merging (Yadav et al., ICLR 2026): interpolating the weights of a fine-tuned policy with the pretrained ones keeps the generalist abilities and beats both models on out-of-distribution variations of the new task; merging only the language-model weights works about as well (Section 6.4, no numbers given). Tested on π0 and π0-FAST, not π0.5. For us: the repair if B-full is the only arm that works and the probes show damage; applying it to π0.5 is our inference.

Also checked: Zero-Gated Cross-Attention (a tanh(α) gate initialised at zero on a frozen language model, evaluated on Falcon-40B only: an exact no-op at initialisation, |tanh α| = 0.0713 at the best checkpoint).

Contact, force and touch in VLAs 19 items

Background for the contact part of the pipeline: the wrench and contact go into the Flight DiT in Phase 2, with contact drawn into π0.5's images as the comparison route.

Three findings matter for the design. Force works best on the action side (TA-VLA). Drawing force into π0.5's images beats feeding it as state (VisForce). Since 2026 the common pattern is a faster, force-reading branch next to the action expert over a cached VLM (LIFT on π0.5, FAVLA on π0; T-Rex does the same inside its own Qwen3-VL-2B model).

Signal as tokens or an encoder

  • TA-VLA: Elucidating the Design Space of Torque-aware Vision-Language-Action Models (Zhang et al., CoRL 2025) Project page closest to us: a systematic study of where torque enters a VLA. Adapters on the decoder (action) side beat adapters on the encoder side, and an auxiliary torque-prediction output helps further. For us: supports feeding the wrench to the action-side Flight DiT rather than to π0.5's VLM, with an auxiliary head that predicts future wrench.
  • TacVLA: Contact-Aware Tactile Fusion for Robust Vision-Language-Action Manipulation (Zhang et al., arXiv 2026) Project page contact gate: LoRA on π0.5 (pi05_base). A 15×8 tactile array is encoded by an MLP into 36 tactile tokens in the VLM prefix, and a contact gate masks them while nothing touches. 83.75% against 63.75% for fine-tuned π0.5 on disassembly and 70% against 10% on in-box grasping; without the gate 71.25% and 40%. For us: the contact gate carries over directly to the contact slot of the Flight DiT and the message, so free flight adds no noise. Its tokens run at 10 Hz in the prefix and do not address the rate question.
  • ForceVLA: Enhancing VLA Models with a Force-aware MoE for Contact-rich Manipulation (Yu et al., NeurIPS 2025) Project page: on π0, a mixture-of-experts module fuses 6-axis force with the VLM embedding at the action decoder. For us: the standard baseline; it fuses at a single rate, which is the contrast to a two-rate design.
  • ForceVLA2: Unleashing Hybrid Force-Position Control with Force Awareness for Contact-Rich Manipulation (Li et al., arXiv 2026): a text force prompt tells the VLM the contact phase, while raw 6D force enters the action expert as one token through a visual, state and force mixture of experts; outputs are pose increments plus a target force. Reported 48% above π0 and 35% above π0.5. For us: the same division of labour as ours: slow semantics of the contact phase in the VLM, raw force on the fast action side.
  • Beyond Sight: Finetuning Generalist Robot Policies with Heterogeneous Sensors via Language Grounding (Jones et al., ICRA 2025) Project page: FuSe fine-tunes Octo and a 3 B PaliGemma VLA with touch and audio, using contrastive and language-generation losses to tie the new modalities to pretrained semantics. For us: if force ever enters π0.5's VLM, language-grounding losses like these limit forgetting.
  • OmniVTLA: Vision-Tactile-Language-Action Models with Semantic-Aligned Tactile Sensing (Cheng et al., RA-L): on π0, touch goes through two encoders, a pretrained ViT and a tactile ViT aligned by contrastive learning, and actions come from flow matching. For us: the dedicated-encoder route; it needs its own tactile dataset, which is costly to build in simulation.
  • Tactile-VLA: Unlocking Vision-Language-Action Model's Physical Knowledge for Tactile Generalization (Huang et al., arXiv 2025): an MLP turns the last H frames of tactile force into one token in the VLM prefix; the action expert outputs target position and target contact force for a hybrid position-force controller. For us: a minimal baseline, and a hint that the action space could include a target wrench.
  • TaF-VLA: Tactile-Force Alignment in Vision-Language-Action Models for Force-aware Manipulation (Huang et al., arXiv 2026): aligns tactile and force signals inside a VLA for force-aware manipulation. For us: another encoder-route reference; not read in detail.

Signal drawn into the image

  • TAP-VLA: Tactile Annotation Prompting for Vision Language Action Models (Van der Merwe et al., arXiv 2026) Project page image route: the GelSight shear field is projected into the shoulder and wrist images as colored segments and π0.5 is fine-tuned with no change to the model. 94 of 120 trials on four tasks; vision only, raw GelSight as an extra view and a CNN encoder all stay below 50%. For us: the image route into π0.5: the drawing arm of the Phase 2 comparison (token only, drawing only, both). It is bound to the camera rate, so it complements rather than replaces the wrench path into the Flight DiT.
  • VisForce: Visual Grounding of Current and Desired Forces for Goal-Conditioned Dexterous Manipulation (Lee et al., arXiv 2026) closest to us: fingertip forces are drawn as 3D arrows (length by magnitude, one color per finger, hidden below a threshold) into the real wrist image through a calibrated virtual camera, and π0.5 is fine-tuned with LoRA. Drawing beats feeding force as state by a wide margin: 65% against 20% and 40% against 5%. For us: almost exactly the drawing arm of our comparison, on π0.5. It never compares with force entering a fast DiT, which is the gap our experiment fills.
  • VTLA: Vision-Tactile-Language-Action Model with Preference Learning for Insertion Manipulation (Zhang et al., arXiv 2025) Project page: tactile image sequences from both fingertips are tiled 2×2 and given to Qwen2-VL 7B next to the camera images, then refined with DPO; data come from Isaac Gym. For us: another way of handing a non-visual signal to the VLM as an image, also built in Isaac simulation.

Fast contact loop next to a slow policy

  • Never Too Late for Force: Accelerating VLA Post-Training with Reactive Force Injection (Wang et al., CoRL 2026) Project page closest to us: LIFT grafts a reactive action expert, copied from the pretrained one, beside the action expert; recent 6D force enters through a causal GRU memory and zero-initialised cross-attention whose output projection starts at zero, so the update is exactly zero at the first step. The full network is post-trained (the paper never says the VLM is frozen; its Section 5.6 trains the whole network), with DAgger-style corrections mixed in. For us: the same shape as a wrench-reading Flight DiT conditioning π0.5's action expert, and the source of our zero-gated ablation entry.
  • FAVLA: A Force-Adaptive Fast-Slow VLA model for Contact-Rich Robotic Manipulation (Li et al., arXiv 2026) closest to us: on π0, the slow VLM runs at a fixed low rate and predicts upcoming force change; the fast action expert reads the newest force tokens by cross-attention in every layer over the cached VLM keys and values. A causal TCN (a 1×1 convolution and four dilated blocks) turns the force history into 4 tokens, and the expert runs max(1, ⌈ν̃·Nmax⌉) times per VLM step, where ν̃ is the predicted force variance; fixed 1, 2 or 4 runs are the baselines. The adaptive rate adds 10 points on both tasks (70% → 80%, 60% → 70%). For us: the tokenizer that packs our 120 Hz history, and a pattern for a rate that follows contact, which is a later ablation.
  • T-Rex: Tactile-Reactive Dexterous Manipulation (Niu et al., arXiv 2026) Project page HTML v2 rate coupling: a 10-step flow denoise is split at τ = 0.4. The slow stream (vision, latent and action experts) runs the first 6 steps once per 16-step chunk and caches its keys and values; a 0.62 B tactile expert finishes the last 4 steps four times per chunk from the newest fingertip-force tokens, without re-running vision. 65% against 35% for the strongest baseline over 12 tasks; in a six-task ablation, removing touch gives 42% and removing the asynchronous split 60%. Training adds a future loss with weight 0.5 and shifts the tactile frames by δ ∈ {0, 4, 8, 12} against the images. For us: the documented route if the message has to reach the chunk π0.5 is executing: π0.5 would denoise part of the way and cache it, and a fast expert would finish from the newest body state. It stays a stretch ablation, since asynchrony is worth 5 points there and touch 23; its future loss and delay shifts are in our Stage A.
  • Reactive Diffusion Policy: Slow-Fast Visual-Tactile Policy Learning for Contact-Rich Manipulation (Xue et al., RSS 2025) Project page: a slow latent diffusion policy predicts latent action chunks at 1–2 Hz and a fast asymmetric tokenizer decodes them at 20–30 Hz with the newest tactile or force reading; force enters only the decoder. For us: the prototype of a slow-fast split, and of a third, wrench-only layer below the Flight DiT.
  • ImplicitRDP: An End-to-End Visual-Force Diffusion Policy with Structural Slow-Fast Learning (Chen et al., RA-L 2026) Project page: one network handles slow visual tokens and fast force tokens with causal attention, plus a virtual-target loss that maps force into the action space so the model cannot ignore it. For us: a remedy if the Flight DiT learns to ignore the wrench.
  • TacMamba: A Tactile History Compression Adapter Bridging Fast Reflexes and Slow VLA Reasoning (Wang et al., arXiv 2026): a Mamba adapter compresses the force history into a compact state in 0.45 ms and plugs into a VLA without joint pretraining; π0.5 is the vision baseline. For us: a light encoder for wrench history above 100 Hz feeding the Flight DiT.
  • ForceDelta-VLA: Distilling Force-Conditioned Action Corrections for Contact-Rich Manipulation (Dong et al., arXiv 2026): a frozen teacher predicts with and without force; the difference is distilled into a light student that corrects actions between chunk updates from the force history. 82.2% against 54.4% for ForceVLA. For us: a way to add force corrections between π0.5's 50-step chunks without touching π0.5.
  • FR-VLA: Implicit Force Reasoning VLA for Contact-Rich Manipulation (He et al., CoRL 2026): learns a force-admission signal that sets how strongly the wrench influences the action. For us: a learned gate, an alternative to TacVLA's fixed contact threshold.

Learned aerial manipulation since the main page 5 items

Direct competitors on aerial platforms, beyond the three already cited on the main page.

No learned aerial manipulation policy with an arm that takes the wrench as an input was found (rechecked on 7 Nov 2026). Flying Hand and Aerial Manipulation in the Wild use no force; the learned flight modules (ALMA, Aco2) adapt from their own history; the aerial works with contact force use hand-designed controllers, and a 2022 aerial-sliding policy learns impedance gains from tactile input but has no arm. A wrench-aware learned policy in the air is open.

  • From Local Whole-Body VLA Behaviors to Scene-Scale Aerial Manipulation (Guo et al., arXiv 2026) closest to us: π0.5 fine-tuned with LoRA (ranks 16 and 32) on a quadrotor with a 3-DoF arm outputs an 8-D whole-body action (arm configuration, gripper, body position and yaw offset from the pose at observation time) as ten waypoints 0.25 s apart, which trajectory optimisation turns into executable motion. Local skills 39 of 60 (65.0%) in simulation; full missions 21 of 50 (42.0%). For us: the closest platform and model, but one whole-body policy: the natural baseline for our split design. We cite it rather than reproduce it: a whole-body π0.5 needs base-joint labels we do not have, and AM-Bench registers a base-joint interface for only 3 of the 12 tasks.
  • AIR-VLA+: Decoupling Movement and Manipulation via Cascaded Dual-Action Decoders with Asymmetric MoE for Aerial Robots (Sun et al., arXiv 2026) closest to us: cascaded manipulation and movement decoders in a flow-matching model; the UAV decoder reads the arm's intent one way, with the arm's tensor detached so movement gradients stay out of the arm. Overall score 48.0 against 42.0 for single-head π0.5 on the AIR-VLA benchmark; the abstract's +80.2% is the task-completion sub-score (10.6 → 19.1). The detach alone moves the score from 40.4 to 45.1. For us: separates flight from manipulation as we do, with the condition flowing arm to body: the precedent for our return channel and its stop-gradient. It reports no direction ablation; ours would be the first on an aerial platform.
  • Adaptive Aerial Loco-Manipulation Policy Learning via LLM-Assisted Proactive Task Generation (Ru et al., arXiv 2026): ALMA's contextual flight policy, which outputs rotor commands, adapts from recent measurements (including the arm's joint positions) and actions while the arm follows external commands, with its context trained to predict future measurements; a language model proposes new arm-motion patterns where tracking is hard. Position RMSE down by up to 24.7% in simulation; zero-shot on hardware, hover RMSE down 79.6% during periodic arm motion. For us: the closest learned flight module: it sees where the arm is but gets no message about what the arm will do. Our return channel gives the Flight DiT the arm's plan. No force input.
  • UMI-on-Air: Embodiment-Aware Guidance for Embodiment-Agnostic Visuomotor Policies (Gupta et al., ICRA 2026) Project page: injects the gradient of the low-level controller's tracking cost into diffusion sampling so the policy proposes trajectories the vehicle can follow; no force input. For us: a precedent for controller feedback shaping the upper generator on an aerial platform.
  • Aerial Manipulation with Contact-Aware Onboard Perception and Hybrid Control (Zhan et al., ICRA 2026): uses contact force through hybrid force-motion control, not a learned policy. For us: the only aerial work found that closes a loop on contact force.

Also checked: Aco2 (contextual meta-RL delivery with a hook on a quadrotor; adapts from interaction history), RL with an inner-loop dynamics estimator (learned whole-body commands from end-effector targets on a quadrotor with a 3-DoF arm), force-aware grasping with skin-like tactile sensors (control not learned), AeroManip-VLA and AIR-VLA (simulation benchmarks; no force input), and a 2022 aerial-sliding policy that sets impedance gains from proprioceptive and tactile input on an omnidirectional vehicle without a manipulator arm.

Loco-manipulation on legged robots 17 items

Quadrupeds with arms, and how VLAs start to be used for the arm.

Most systems stack a visual or VLA policy on an RL whole-body or locomotion controller, talking through end-effector pose or trajectory plus body velocity (VBC, UMI on Legs, LEGS, FALCON). VLAs arrived from late 2025, almost always fine-tuned to output both arm and base commands. Keeping a pretrained VLA for the arm and feeding a separately learned body module back into it as a token was not found; FWBC-VLA and HAF come closest, and DUET keeps the arm VLA swappable over a learned locomotion policy but sends nothing back to it.

VLA or foundation model for the arm on a legged base

  • FWBC-VLA: Force-Aware Whole-Body Compensation for Contact-Rich Loco-Manipulation (Zhang et al., arXiv 2026) closest to us: on a wheel-legged quadruped with a 6-DoF arm, fully fine-tuned π0.5 outputs arm, gripper and nominal base velocity for a whole-body controller; a separate module estimates contact force from residual torque, encodes it with a GRU into a token that enters π0.5's action expert by cross-attention, and a compensation MLP adds a base-velocity residual. Average success 12.0% without force, 35.0% with the force tokens and 65% with the compensation as well (59.5% in the text). For us: almost our structure, π0.5 plus a small separate module injecting a token into the action expert, but the token carries force rather than motion intent and π0.5 is not kept as is.
  • From Tabletop to Walking Bot: Deploying a VLA Model on a Legged Manipulator Robot (Minelli et al., arXiv 2026) closest to us: on a Go2 with a Piper arm, MolmoAct2 fine-tuned with LoRA outputs an 11-D command (base twist, body pitch, six arm joints, gripper); an arm-aware RL gait policy executes the base part. For us: the most direct case of moving a tabletop-pretrained VLA to a legged robot, though the VLA itself drives the base.
  • FALCON: Actively Decoupled Visuomotor Policies for Loco-Manipulation with Foundation-Model-Based Coordination (He et al., arXiv 2025) Project page closest to us: on a Go2 with an Airbot arm, two separate diffusion policies (base velocity, pitch and height to an RL controller; end-effector position to IK) are coordinated by a shared latent fused from frozen CLIP features with task phase and progress. For us: a shared conditioning latent between arm and base, like our token, but both policies are trained from scratch on 50 demos.
  • UMI on Legs: Making Manipulation Policies Mobile with Manipulation-Centric Whole-body Controllers (Ha et al., CoRL 2024) Project page closest to us: a manipulation policy outputs end-effector trajectories in the task frame and an RL whole-body controller tracks them; a checkpoint trained for a fixed-base arm runs zero-shot on a quadruped. For us: shows a pretrained arm policy can stay unchanged while the body absorbs the motion; information flows arm to body, the reverse of ours.
  • QUAR-VLA: Vision-Language-Action Model for Quadruped Robots (Ding et al., ECCV 2024): the first quadruped VLA (QUART models, QUARD dataset); one model outputs locomotion and manipulation commands. For us: the single end-to-end route, with no arm and base split.
  • Helpful DoggyBot: Open-World Object Fetching using Legged Robots and Vision-Language Models (Wu et al., arXiv 2024) Project page: a quadruped with a front gripper; a pretrained VLM handles semantics and an RL controller trained in simulation on depth does the climbing and leaning. For us: the foundation model plans only and outputs no actions.
  • ODYSSEY: Open-World Quadrupeds Exploration and Manipulation for Long-Horizon Tasks (Wang et al., arXiv 2025) Project page: a hierarchical VLM planner decomposes long tasks over a two-stage RL whole-body controller that tracks end-effector targets. For us: VLM planning on an RL whole-body controller, again with no VLA on the arm.

Humanoids with VLAs

  • WholeBodyVLA: Towards Unified Latent VLA for Whole-Body Loco-Manipulation Control (Jiang et al., ICLR 2026): on AgiBot X2, a VLA at about 10 Hz decodes both arms' joints and discrete locomotion commands (forward, turn, squat) for a 50 Hz RL locomotion policy. For us: the typical pattern: the VLA drives the hands and commands the legs through an RL controller.
  • LEGS: Fine-Tuning Teleop-Free VLAs for Humanoid Loco-manipulation in an Embodied Gaussian Splatting World (Kim et al., CoRL 2026) Project page: π0.5, ψ0 and GR00T N1.6 fine-tuned on a G1 output an 18-D command (two wrist 6D poses, grippers, base vx, vy, ωz and height) for an RL controller. For us: π0.5 outputting end-effector and base velocity, the most common interface.
  • HAF: Adapting Generalist VLAs to Humanoid Whole-Body Loco-manipulation via Hierarchical Action Flow and Spectral Latent RL (Gu et al., arXiv 2026): a π0.5-based model denoises in three levels (locomotion and skill mode, then waist, then arms), then adapts with RL only in the noise subspace over a frozen backbone. For us: keeps π0.5 frozen and adapts from outside, though locomotion is still generated by the VLA.
  • DUET: Decoupled Upper- and Lower-Body Execution for Task-Agnostic Humanoid Loco-Manipulation (Khanal et al., arXiv 2026) closest to us: on a 23-DoF G1, an RL policy drives the 12 leg joints and the waist yaw and sees the 10 arm joints only as observations, so any arm policy that outputs arm-joint targets can run on top; the same checkpoint was paired with GR00T N1.7 and π0.5 without retraining. Tracking errors of 0.186 m/s, 0.142 rad/s and 0.016 m, and no falls under pushes up to 1.0 m/s. For us: the cleanest case of a swappable arm VLA over a learned body controller. Nothing goes back to the arm, which is the part we add.
  • LeVERB: Humanoid Whole-Body Control with Latent Vision-Language Instruction (Xue et al., arXiv 2025): on a G1, a 10 Hz high-level VLA emits latent verbs that a 50 Hz RL whole-body controller executes. For us: a latent-token interface, flowing from the VLA to the controller, the reverse of ours.

Whole-body learned policies

  • Visual Whole-Body Control for Legged Loco-Manipulation (Liu et al., CoRL 2024) Project page: VBC: on a B1 with an arm, a high-level visual policy outputs end-effector pose and body velocity, and a low-level RL policy tracks them with every joint. For us: set the standard interface of end-effector pose plus body velocity; both levels trained from scratch.
  • RoboDuet: Learning a Cooperative Policy for Whole-body Legged Loco-Manipulation (Pan et al., arXiv 2024) Project page: separate locomotion and arm policies; the arm policy sends body-pose commands to the locomotion policy; two-stage training. For us: split modules that transfer across bodies, with information flowing arm to base.
  • LocoMan: Advancing Versatile Quadrupedal Dexterity with Lightweight Loco-Manipulators (Lin et al., arXiv 2024) Project page: 3-DoF manipulators on a Go1's front calves under one model-based whole-body controller. For us: the hardware and model-based route, with no learned arm policy.

Teleoperation and data

  • WildLMa: Long Horizon Loco-Manipulation in the Wild (Qiu et al., arXiv 2024) Project page: VR whole-body teleoperation through a learned whole-body controller, an ACT and CLIP skill library from imitation, and an LLM planner on top. For us: the whole-body controller doubles as teleop and policy interface, which cuts demo cost.
  • Human2LocoMan: Learning Versatile Quadrupedal Manipulation with Human Pretraining (Niu et al., arXiv 2025) Project page: unifies human and LocoMan observations and actions, pretrains on human data and fine-tunes on robot data; 38.6% higher overall and 82.7% higher out of distribution. For us: another route to a pretrained arm policy across bodies.

Also checked: GeRM (mixture-of-experts offline RL for quadrupeds, simulation only), MoE-Loco (locomotion only, no arm), AGILE (an end-to-end RL workflow for humanoid loco-manipulation) and GRAIL (demonstrations generated from video world models; an object-aware latent adaptor drives a tracker).

Mobile manipulation on wheeled robots 15 items

Mobile robots with arms, and how VLAs start to be used for the arm.

Three routes exist. A fixed VLA works after an optimised or planned base pose, with the VLA unaware of the base (MoManipVLA, MoTo, N2M). One whole-body policy concatenates base velocity into the action or conditions arm on base inside the model (Mobile ALOHA, BEHAVIOR Robot Suite, PanoVLA). One-way base-to-arm conditioning (HiRe-MoMa) and modules inserted into π0.5 (PanoVLA) appeared in 2026 but have not been combined, which is what our design does.

Pretrained arm policy plus a separate base module

  • Hierarchical Residual Policy Learning for Real-World Mobile Manipulation with Sparse Human Guidance (Gong et al., CoRL 2026) Project page closest to us: HiRe-MoMa learns residuals on a frozen base policy (Diffusion Policy or ACT) with separate base and arm heads; the base residual is computed first and fed to the arm head. TIAGo++. For us: one-way base-to-arm conditioning, the closest structure to the Flight DiT passing a token to π0.5, though the frozen policy is not a VLA.
  • MoManipVLA: Transferring Vision-language-action Models for General Mobile Manipulation (Wu et al., CVPR 2025) Project page closest to us: OpenVLA-7B with LoRA outputs end-effector waypoints, and a bi-level optimisation (base pose search, then IK for the arm) makes them reachable on a Stretch. For us: keeps the pretrained VLA and adds a base module, but the base is an untrained optimiser and the VLA never sees the base.
  • MoTo: A Zero-shot Plug-in Interaction-aware Navigation for General Mobile Manipulation (Wu et al., CoRL 2025) Project page: a VLM marks interaction keypoints on the object and the arm, a docking base pose is optimised, then a fixed-base model (OpenVLA, RDT-1B, iDP3) does the manipulation. For us: move then manipulate, with no condition between the two; the authors note the viewpoint shift this causes for the VLA.
  • N2M: Bridging Navigation and Manipulation by Learning Pose Preference from Rollout (Chai et al., arXiv 2025) Project page: a learned transition module that picks the initial base pose the manipulation policy prefers, from rollouts; policy-agnostic. For us: a learned base module, but it acts only before manipulation starts.
  • Cracking Mobile Manipulation: From Failure Diagnosis to Agentic Robot System (Wang et al., arXiv 2026): fixed sub-task VLAs reach 80% on atomic skills but 19% when composed into mobile manipulation; four failure-guided interventions (planning guidance from demonstrations, adaptive visual memory, accessibility-aware base adjustment, local end-effector adjustment) lift RoboCasa365 step by step from 19% to 47%. For us: composing fixed arm skills on a moving base is where success collapses, and two of the four fixes move the base or the end effector, an argument for a dedicated base module; theirs are hand-designed.
  • Harness VLA: Steering Frozen VLAs into Reliable Manipulation Primitives via Memory-Guided Agents (Zhang et al., arXiv 2026): a frozen VLA is called only for contact phases, analytic primitives handle navigation and the base, and a memory-equipped LLM agent orchestrates them. For us: also keeps the VLA frozen, but switches discretely between primitives instead of conditioning continuously.
  • BUMBLE: Unifying Reasoning and Acting with Vision-Language Models for Building-wide Mobile Manipulation (Shah et al., arXiv 2024) Project page: a VLM schedules a coarse-to-fine skill library across floors and manipulation. For us: the VLM-orchestrates-skills route, with no end-to-end arm VLA.

Whole-body imitation policies

  • Mobile ALOHA: Learning Bimanual Mobile Manipulation with Low-Cost Whole-Body Teleoperation (Fu et al., arXiv 2024) Project page: one ACT policy outputs both arms' joints and base velocity, co-trained with static ALOHA data. For us: the baseline of one concatenated whole-body action, no split.
  • TidyBot++: An Open-Source Holonomic Mobile Manipulator for Robot Learning (Wu et al., CoRL 2024) Project page: an open holonomic base with one arm, phone teleoperation, and one diffusion policy for base and arm. For us: a hardware and data platform; the policy is whole-body.
  • BEHAVIOR Robot Suite: Streamlining Real-World Whole-Body Manipulation for Everyday Household Activities (Jiang et al., CoRL 2025) Project page: on a Galaxea R1, WB-VIMA predicts along the kinematic chain, base first, then torso, then arms, each conditioned on the ones before. For us: base-to-arm conditioning inside one model, the same direction as ours, but not from a pretrained VLA.
  • EMMA: Scaling Mobile Manipulation via Egocentric Human Data (Zhu et al., arXiv 2025) Project page: a shared HPT-based trunk with a navigation head (x, y, ω) trained mostly on Aria-glasses human data and an arm head; a predicted phase switches between them. For us: shared trunk, split heads, phase gating, and no pretrained VLA.

VLA-based mobile manipulators, 2025–2026

  • Learning Panorama-Aware VLA for Mobile Manipulation with Whole-Body Teleoperation (Yang et al., arXiv 2026) closest to us: PanoVLA inserts a roughly 100 M-parameter panorama expert between π0.5's VLM and action expert; the action is a 17-D whole-body vector (14 arm dimensions plus base vx, vy, ω). For us: adds a module inside π0.5 as we do, but π0.5 still outputs the base actions itself.
  • MoPA: Coordinated Mobile Manipulation via Subsystem-Specific Perception Alignment (Chen et al., arXiv 2026) Project page: on a shared Qwen3-VL context, base and arm each get masked queries, and a mixture-of-transformers decoder exchanges the two action streams' state in every layer through coupled flow matching; π0 is a baseline. For us: two streams with per-layer exchange, a symmetric many-token version of our two modules and their message.
  • Galaxea Open-World Dataset and G0 Dual-System VLA Model (Jiang et al., arXiv 2025) Project page: a Qwen2.5-VL planner and a PaliGemma-based VLA executor drive base, torso and both arms of an R1 Lite. For us: the industry pattern of treating the base as more action dimensions.
  • Per-Group Error, Not Total MSE: Fine-Tuning Vision-Language-Action Models for 11-DoF Mobile Manipulation (Montagut Bofi et al., ICRA 2026 workshop): SmolVLA and π0.5 fine-tuned to an 11-D action on a Toyota HSR. The checkpoint with the lowest total MSE, a π0.5 variant with the PaliGemma2 backbone frozen, scored 3.75 of 4 on hardware against 4.0 for the full fine-tune (20 trials each, p = 0.010), and the arm-group error (0.59 against 0.30) predicted the gap better than the total. For us: report end-effector position, orientation and gripper errors separately rather than one total loss, and a reminder that freezing the VLM is not known to be better, only easier to attribute.

Also checked: CheckVLA (a frozen action-conditioned world model checks each chunk as it runs and triggers repairs: 36.1% against 27.6% for periodic re-planning on RoboCasa365).
